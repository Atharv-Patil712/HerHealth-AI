# Deploy the HerHealth API on Render

The `render.yaml` Blueprint deploys the FastAPI backend on Render's free
instance plan. The existing frontend is managed separately.

## Deploy from GitHub

1. Push this repository, including `render.yaml`, to GitHub.
2. In [Render](https://render.com), select **New → Blueprint** and connect the
   repository.
3. Review and deploy the `herhealth-ai-api` service.

The Blueprint sets the backend build and start commands, health check, and CORS
origin. The expected API hostname is `https://herhealth-ai-api.onrender.com`,
which is also the frontend's production default. If Render assigns a different
hostname, update `VITE_API_BASE` in the frontend and `CORS_ORIGINS` in the
backend to match, then redeploy both services.
The free API instance may sleep when idle and has limited memory and CPU.

Render's local filesystem is ephemeral unless a persistent disk is attached.
The backend stores screening and questionnaire records in SQLite, so those
records and the generated Q&A index can be lost when the service restarts or
redeploys without persistent storage. The knowledge-base build downloads and
indexes its dataset during deployment; app startup creates the SQLite schema.

Local development uses the Vite proxy when `VITE_API_BASE` is unset.

## Screening image validation

The screening page requires both an inner-eyelid photo and a fingernail photo.
JPEG, PNG, WebP, and HEIC/HEIF photos are accepted (HEIC/HEIF decoding uses
`pillow-heif`). Uploads are sent to the HerHealth backend for processing; this flow does not send
uploaded images to Hugging Face Inference and does not require an `HF_TOKEN`.
The eyelid image is checked by the local conjunctiva detector, with center-crop
fallback disabled. Both routes reject blank or very dark images. The fingernail
model does not reliably verify that an image actually contains a nail, so its
estimate must be treated as experimental. A reliable nail-image check requires
a task-specific model and validation data.

## What's Included

- `src/` — All React components, pages, and logic
- `vercel.json` — Vercel build configuration
- `package.json` — Dependencies and scripts
- `vite.config.ts` — Vite configuration with API proxy
- `tailwind.config.js` — Theme colors and fonts
- `index.html` — Entry point
- `.env.example` — Environment variable template

## What's NOT Included

- `node_modules/` — Will be installed by Vercel automatically
- `dist/` — Build output, generated by Vercel automatically
- `.env` — Create this from `.env.example` with your production API URL
